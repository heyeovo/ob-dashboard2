### 验收

## ✅ P0：事件日期写入与 `breath(date=...)` 不一致（2026-08-10 已解决）

### 完成状态

- `hold(date="YYYY-MM-DD")` 写入的 `metadata.event_time` 已成为事件时间事实源，保留完整时间时按北京时间年月日查询。
- `breath(date=...)` 已统一按 `event_time` 匹配、排序和展示；缺失时兼容旧 `metadata.date`，两者都没有才回退到创建、更新或活跃时间。
- 存量迁移不会覆盖已有 `event_time`；缺失值优先从旧 `date` 补齐，再回退到 `created`。
- 前端桶抽屉的事件日期选择器已确认会经代理 PATCH 到 Haven，并由后端 `bucket_mgr.update(event_time=...)` 持久化；当前控件修改日期并保存为当天 `00:00:00`，不单独编辑时分秒。

### 已确认的目标口径

- LLM 写事件桶时传 `date="YYYY-MM-DD"`。
- 后端以 `event_time` 作为事件时间事实源，同时兼容旧 `date` 数据。
- `breath(date=...)` 优先按事件时间匹配；没有事件时间的旧桶才回退到创建等时间。

### 验收

- 在另一天创建一条 `date="2026-08-01"` 的桶。
- `breath(date="2026-08-01")` 能命中。
- 查询实际建桶日期时不会因为 created 时间错误带出该事件桶。

## P1：journey 隔离、读取与后台生成

### 第一阶段完成状态（2026-08-11）

- journey 已成为独立 `relationship_journey` 记忆层，普通关键词、向量、日期、词法补召、开窗浮现、写入合并候选和 bucket/moment 关联扩散均排除。
- dashboard `/api/search` 为人工管理显式放行，记忆库和人工搜索仍可看到 journey。
- `breath(domain="journey")` 已改成只返回桶 ID、阶段标题、起止时间和一句摘要；选择后用 `read_bucket(bucket_id)` 读取全文。
- 旧 journey 缺少新结构化字段时，目录会回退到事件/创建时间和正文第一条有效行，不要求先迁移旧桶。
- 已增加 journey 隔离专项测试；Haven 全量 39 项测试通过。
- 第一阶段只完成隔离与读取；写入权限和阶段状态的后续完成情况见下方第二阶段。

### 第二阶段完成状态（2026-08-11）

- 公共 `hold(journey=True)` 与 `hold(domain="journey")` 已硬拒绝，保留参数仅用于旧客户端兼容。
- 普通 MCP 的 `comment_bucket`、`delete_bucket_comment` 和 `trace` 均不能追加、修改或删除 journey；dashboard 认证编辑仍保留人工纠错能力。
- 后台已具备开放阶段创建、同阶段追加和阶段关闭三个内部操作；同一时间只允许一个 `journey_status=open`。
- 后台只能追加开放阶段，关闭后写 `journey_status=closed` 与 `journey_end`；旧 journey 不会被自动认定为开放阶段。
- 后台操作支持 `operation_id` 幂等去重，并累计关键事件 `journey_source_bucket_ids`。
- 尚未实施：每周判断任务、实际阶段切换编排和历史断档补录。

### 当前问题

- journey 的目标是不参与普通浮现和召回，但当前实际仍可能被正常召回。
- `breath(domain="journey")` 当前倾向于一次返回全部轨迹，缺少“先看目录、再读全文”的两步读取。
- 窗口切换频率高于人生阶段切换频率，不能由单个窗口直接创建新轨迹桶。

### 已确认的目标口径

- 一个阶段对应一个 journey 桶。
- journey 是关系阶段的状态总结和关键记忆上层索引，不是所有日常记忆的汇总。
- 内容包括阶段名称、起止时间、第一人称关系状态、关键事件桶 ID + 标题、认知更新和一句摘要。
- 当前阶段桶保持开放，由后台任务在同一阶段延续时追加；出现关系状态或相处模式的实质切换后，关闭旧桶并创建新桶。
- 已关闭的历史阶段桶冻结，不再自动修改或追加。
- journey 不参与普通浮现和召回。
- journey 与普通记忆的关联扩散隔离；它对关键事件桶的引用不能把 journey 反向带入普通召回。
- dashboard 记忆库仍可查看 journey，隔离范围只针对 LLM 的普通召回链路。
- 读取时先返回阶段、时间范围、标题和一句摘要，再由 LLM 选择具体桶读取全文。
- 单窗口只能提出轨迹候选，不能直接执行 `hold(journey=True)`。
- 后台轨迹整理任务每周独立运行一次，携带 LLM 身份与双方关系提示词。
- 每周输入包括：当前开放 journey、最近一周日回顾、本周新建桶、独立 feel、旧桶本周新增的 feel 年轮，以及未来接入的语录；材料按桶 ID 去重。
- 日回顾负责判断关系状态变化，普通桶负责提供可验证的关键事件 ID 与标题。
- 无实质变化时不修改；同阶段延续时追加当前桶；关系状态或相处模式改变时关闭旧桶并创建新桶。
- 每周任务保存检查进度并保证幂等，重复执行不能重复追加。

### 实施顺序

1. journey 隔离与两步读取：堵住普通搜索、语义召回、自动浮现和关联扩散入口，同时保留 dashboard 可见和显式读取。
2. 当前/历史阶段状态：开放桶可追加，关闭桶冻结，普通窗口不能直接创建 journey。
3. 持续自动化：接入每周独立任务，读取 Haven 内日回顾、桶、feel 和当前 journey。
4. 历史断档补录：完成聊天原文档案导入后，对 2026 年 5 月以后缺失阶段分段整理；先生成预览，经人工确认后写入。

### 验收

- 普通 query 不返回 journey。
- journey 目录只返回精简列表，不直接灌入全部全文。
- 选择一条后可读取对应完整轨迹桶。
- 多次换窗不会自动产生多个阶段桶。
- 同一周任务重复运行不会重复追加。
- 普通桶的关联扩散不会反向带出 journey。
- 当前阶段可持续更新；一旦关闭，后台任务不再改写。

## P1：moments 可观测性与自动摘要价值

### 当前问题

- 前端记忆桶抽屉没有 moments UI，用户看不到一个桶被拆成了哪些 moments，也看不到桶内和跨桶关联。
- 当前直接召回会用 moment 定位，但 token 预算足够时仍返回整个桶全文。
- 后端自动生成的 `### moment` 会写回正文；短桶中可能与正文重复，且曾出现截断、信息价值低的摘要。

### 已确认的产品口径

- moment 用于后台定位、排序、关联和扩散。
- 命中桶后继续向 LLM 返回桶全文，保证事件、原话、reflection 和年轮都有上下文。
- `original`、`reflection` 属于正文分段；年轮依附桶，不在正文 content 中。
- 是否继续把自动摘要写回可见正文，需要结合 UI 和实际召回效果另行评估。

### 前端 UI 目标

在桶抽屉增加 Moments 区域，至少展示：

- moment 类型：body / moment / original / reflection / comment 等；
- 内容预览与 moment ID；
- 桶内关系及关系类型；
- 跨桶关系、目标桶标题和关系类型；
- 点击目标后可查看对应桶。

### 验收

- 任意结构化桶都能看到实际 moments。
- 能区分桶内关联和跨桶关联。
- 能据此判断自动 `### moment` 是否确实提升了检索或只是重复正文。

## P2：Claude 官方端开窗适配

### 背景

当前 API 前端已经自动注入 handoff，不需要调用 `breath(is_session_start=True)`。Claude 官方端若只通过 MCP 使用 OB，则缺少同等开窗背景。

### 目标

让 Claude 官方端通过一次 session-start breath 获得接近 API 前端的开窗内容：

- 所有 pinned 桶；
- 最近 N 个普通记忆桶；
- 必要时的最近 N 轮原文；
- 近几天独立日回顾；
- 已存在的自我、用户和关系画像。

日回顾仍独立存储，不进入普通记忆桶，也不参与普通语义召回。

### 验收

- API 前端继续使用自动 handoff，不重复调用 session-start breath。
- Claude 官方端一次调用即可获得足够的开窗连续性。
- 两端开窗内容边界清楚，不重复注入。
